# SAGE Pass 批次调度数学模型

本说明定义 B 负责的决策问题和第一阶段可执行基线。目标是在时间和候选双预算内恢复尽可能多的不同目标，为后续 UCB、成本感知选择及实验评价提供统一口径。依据为《任务安排.docx》《BC参考(1).docx》和当前 scheduler.py；附件提到的《多臂老虎机问题构建.pdf》原文尚未提供，以下混合模型仅依据参考文档转述。

## 模块关系

Planner 根据 PRIR、信息摘要和历史抽象知识确定可用 Arm、优先级和初始预算。Generator 提供有序候选。Scheduler 选择 Arm、提交大小和执行时间上限。Executor 验证所选候选并反馈计数与耗时。run 内反馈更新调度统计，run 间 Feedback 提取抽象 Pattern Knowledge。

Scheduler 不读取回放命中表或未测试目标口令，也不生成候选。个人信息和历史口令仅以 C 提供的脱敏 InformationProfile 摘要进入未来上下文模型。

## 符号与任务定义

| 符号 | 含义 |
|---|---|
| G | 当前目标组，包含有限个匿名目标 |
| U0 | 初始目标数，U0 > 0 |
| I | Planner 允许的有限 Arm 集合 |
| i | 一个目标组、生成器、参数配置的组合 |
| Di | Arm i 的有序有限候选流 |
| t | 批次决策轮次，从 1 开始 |
| Rt | 决策前已恢复目标集合 |
| Ht | 决策前已提交候选集合 |
| ki,t | Arm i 的流游标 |
| Cmax、Tmax | 总提交候选预算与总执行时间预算 |
| Ci,max、Ti,max | Arm i 的局部预算 |
| ΔCt | 本批实际提交的唯一候选数 |
| Vt | 本批完成验证的候选数 |
| Zt | 本批至少新增恢复一个目标的候选数 |
| ΔUt | 本批新增且全局去重后的恢复目标数 |
| ΔTt | 本批含启动开销的执行时间 |
| Ot | 当前扫描前缀的重复比例 |

候选在不同生成器之间可能重叠；同一候选可能匹配多个目标。成立的是 0 ≤ Zt ≤ Vt ≤ ΔCt，而不是 ΔUt ≤ Vt。始终有 0 ≤ ΔUt ≤ U0 - |Rt|。

## 状态与可观测信息

概念状态定义为：

\[
s_t=(x,z,C_t^{rem},T_t^{rem},\{C_{i,t}^{rem},T_{i,t}^{rem},n_{i,t},V_{i,t},Z_{i,t},U_{i,t},G_{i,t},k_{i,t}\}_{i\in I}, |R_t|,a_{t-1}).
\]

x 是目标类型、算法参数、目标数、盐分组及成本摘要；z 是信息条件摘要；n 为已执行批数；V/Z/U 为累计测试候选、命中候选与新增目标；G 为近期收益。

数学上的系统状态还包含 Ht、Rt 和候选流。实现把这些放在环境或执行层，策略只接收可用批次数量和已观察反馈，避免泄露未来命中信息。

第一版 BaselinePolicy 实际使用预算、优先级、候选可用量和历史命中统计。x、z 的学习以及多目标组联合调度未实现；不能把当前三种基线报告为已实现完整 Contextual Bandit。

## 动作与批次消费

一般动作是：

\[
a_t=(i_t,b_t,\tau_t,\theta_{i_t}).
\]

其中 i 是 Arm，b 是提交候选上限，τ 是执行时间上限，θ 在本次实现中已固定为 parameter_profile。第一版默认批次上限由场景配置给定，算法仅按剩余预算截断，并不学习最优批次大小。

候选上限取下列各项的最小值：当前 Arm 可提供的去重候选量、配置批次上限、局部剩余候选预算、全局剩余候选预算。时间上限取局部与全局剩余执行预算的最小值。

只有被选中的候选前缀推进游标。环境按实际提交顺序全局去重。候选提交后计入 Ht，即使超时未验证，也不在后续批次重新提交。重复条目不计入 ΔCt。

## 目标函数与奖励

主要评价目标：

\[
\max_\pi\;\mathbb{E}_\pi\left[\sum_t\Delta U_t\right],\qquad
\sum_t\Delta C_t\le C_{max},\quad\sum_t\Delta T_t\le T_{max}.
\]

每个 Arm 同时满足对应的候选与时间局部约束。奖励建议式为：

\[
r_t=\alpha\frac{\Delta U_t}{U_0}
-\beta\frac{\Delta T_t}{T_{max}}
-\gamma\frac{\Delta C_t}{C_{max}}
-\eta O_t,
\qquad
O_t=\frac{duplicates_t}{\max(1,offered_t)}.
\]

α、β、γ、η 为非负参数且 α > 0。这个标量奖励是主目标的代理，加入成本和重复惩罚后不自动与原约束优化等价。硬预算仍须独立执行，不能只依赖奖励惩罚。

辅助指标定义为：

\[
Gain_t^{candidate}=\frac{1000\Delta U_t}{\max(1,\Delta C_t)},\qquad
Gain_t^{time}=\frac{\Delta U_t}{\max(\epsilon,\Delta T_t)}.
\]

当前实现保存计算这些量所需的原始反馈，但没有交付统一加权奖励计算器，也没有让旧基线改用该奖励；它属于计划第四步。权重只能在训练/验证或预实验阶段选择，测试集评估前固定。

## 状态更新

设本批新增目标集合为 Nt，由执行层相对于 Rt 去重得到：

\[
R_{t+1}=R_t\cup N_t,\quad\Delta U_t=|N_t|,
\quad H_{t+1}=H_t\cup B_t.
\]

\[
C_{t+1}^{rem}=C_t^{rem}-\Delta C_t,\quad
T_{t+1}^{rem}=T_t^{rem}-\Delta T_t.
\]

对选中的 Arm，n 增 1，V 增 Vt，Z 增 Zt，U 增 ΔUt，时间与提交量累加；未选中的 Arm 不更新反馈统计。

### 现有启发式的明确语义

为复用单候选 Bernoulli 形式，兼容层将成功量定义为 Z，而将目标数量 U 单独记录：

\[
\hat p_i=\frac{Z_i+0.5}{V_i+1},\qquad
P_i(b)=1-(1-\hat p_i)^b.
\]

\[
g_t=\min(1,1000Z_t/\max(1,V_t)),\quad
G_{i,t+1}=\begin{cases}g_t&n_i=0\\0.5g_t+0.5G_{i,t}&n_i>0.\end{cases}
\]

\[
Score_i(b)=0.45P_i(b)+0.30G_i+0.15Prior_i
-0.10\min(1,T_i/T_{i,max}).
\]

Prior 是显式 transfer_score，缺省为 1/priority。先按优先级对每个仍可执行 Arm 探索一次，再取最高评分；同分按优先级和 arm_id 稳定选择。上述概率是延续原实现的启发式近似；有序、重叠、已恢复目标和耗尽会破坏独立同分布假设，不能将其直接解释为经过校准的真实恢复概率。

Fixed Order 依次用完最高优先级可用 Arm，再转下一个。Round Robin 在可用 Arm 间轮转，一次一个批次。三者共享相同预算、去重和停止规则。

## 验证成本与时间预算

最小回放提供人工配置的固定成本：

\[
T(i,b)=T_{startup,i}+b\cdot t_{candidate,i}\cdot J_t,
\]

Jt 缺省为 1，启用 time_jitter 时由固定种子的均匀随机数产生。启动开销不乘 Jt；它每批计一次。成本是整个当前目标组的每候选验证成本，第一版不会自动乘目标数或盐组数，也不会随已恢复目标数变化。

若时间上限 τ 不足，实际测试量为：

\[
V_t=\min\left(\Delta C_t,\max\left(0,\left\lfloor\frac{\tau_t-T_{startup}}{t_{candidate}J_t}\right\rfloor\right)\right),
\quad\Delta T_t=\min(\tau_t,T(i,\Delta C_t)).
\]

不足启动时间时 Vt=0，仍消耗已提交候选和所允许的执行时间。批次在回放中标为已处理，超时通过 message 表示；这不意味着目标任务已全部恢复。完成全部目标后在批次边界停止，当前批次仍按上述成本计费。

本次没有测量真实验证成本。实测启动成本、滑动吞吐、多盐组成本与置信度属于后续成本标定器。真实系统的进程启动/终止延迟可能超过请求时间上限，A/B 集成时须区分仿真硬截止与真实时间偏差。该执行时间口径不包含暂停、人机等待、候选离线训练和 Python 调度开销；完整实验应另报端到端墙钟时间。

## 停止性与预算不变量

停止优先级为：所有目标已恢复、总候选预算耗尽、总时间预算耗尽、所有候选耗尽、所有剩余 Arm 的局部预算耗尽。用户取消、执行失败是生产执行层负责的额外终止条件，本次回放不模拟这两种事件。

每次有效 step 至少提交一个从未提交过的候选。设各流唯一候选并集大小为 N，则执行批次数不超过 min(N,Cmax)，因此有限时间内结束，不会因连续零收益永久循环。空流或全重复流没有可用批次，直接停止。

候选预算证明：初始消耗为 0；每次 ΔCt 被全局与局部剩余量截断；归纳得所有前缀的消耗不超过预算。时间在理想回放中按剩余额度截断，实数算术下同样成立；浮点实现需在边界使用数值容差，而真实进程截止需另行验证。

## 混合概率权重与未来算法

参考文档描述：每个生成器提供 pi(w)，取 qi ≥ 0 且 Σqi=1，构造 Qq(w)=Σqi pi(w)，再根据观察拟合 q。q 可作为生成器先验、冷启动排序或候选混合权重。

当前代码只有 Planner 优先级/transfer_score 先验，并没有实现 pi 校准、似然拟合或 q 优化。不同生成器原始概率能否比较、负例采样和似然独立性假设必须先定义。没有 PDF 原文时不声称已证明其凸性，也不把 q 当作已实现的 Bayes 后验。

主问题可描述为具有上下文、双预算、有限候选耗尽和非平稳收益的 Bandit 决策问题。历史去重集合会影响未来可行候选，完整环境包含状态转移；Bandit 是工程近似。后续先接入标准 UCB，再加入预计成本、折扣/窗口或上下文特征。不能把经典平稳 Bandit 的 regret 保证直接套用到这里。

## 最小闭环伪代码

```text
固定场景、候选顺序、命中表、成本参数和随机种子
构造同一 DecisionPolicy 接口下的一个基线
初始化候选游标、已提交集合、已恢复目标集合
while 未满足停止条件:
    仅向策略提供各 Arm 下一批的可用数量
    decision = policy.select(available_sizes)
    按 decision.candidate_limit 取去重前缀，保留未选后缀
    环境按时间上限计算 tested，并查表获得新增目标
    构造 DecisionFeedback，调用 policy.observe_outcome
    更新集合和游标，保存前状态、决策、反馈、后状态
    可在此批次边界 snapshot
输出逐批轨迹与候选量、时间、恢复目标数
```

## 实验解释与复杂度

比较三个算法时固定候选流、目标、预算、成本配置和种子；同一随机种子序列按批次消耗，因此不同决策长度下的随机波动不能解释为同一候选的固定实测成本。正式成本感知比较应先用 time_jitter=0 做控制，再用多个配对种子检验波动。

按用户或来源分组划分训练/验证/测试；候选与先验不得预先利用测试目标。当前合成场景只验证机制，不证明实际恢复率优势。主报告使用 recovered_targets 与 simulated_seconds 等原始量，不将演示输出包装成真实工具测量。

旧调度器单次选臂约 O(K)，K 为 Arm 数。回放为了无副作用地预览每个 Arm，会重复扫描其当前前缀；极端重复流下每轮可扫描 O(N)，这是小规模 MVP 的已知性能边界。集合/候选表约 O(N+U0)，完整轨迹约 O(rounds×K)。前缀重放恢复耗时与历史轮次成正比；流式去重索引和直接恢复留待规模扩大时实现。
